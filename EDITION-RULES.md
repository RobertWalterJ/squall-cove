# Squall Cove: edition rules (every change must pass)

One codebase, two editions: `ed-desktop` (the most capable) and `ed-phone` (a subset with a different layout). Detail and rationale: `MOBILE-UX-PLAN.md`.

1. **Scope phone CSS.** Every phone-only rule lives under `body.ed-phone` or `html.ed-phone`, and rules for the touch controls (first-person stick, buttons, squad ring) live under `body.touch`, which is also true on a tablet in the desktop edition (landscape rules add `@media (orientation:landscape) and (max-height:480px)` inside that scope). Shared rules stay edition-neutral. Never change a desktop rule to fix a phone problem; override it under `.ed-phone`. `qa/css-lint.mjs` fails the release on a phone control styled outside those scopes (the few shared base rules are listed with reasons in `qa/css-scope-allow.json`).
1a. **One stacking ladder.** Every `z-index` of 3 or more is a `--z-*` token defined once in `:root` (under, hud, ctl, feed, pane, fx, sheet, menu, sheet-top, intro, loading, boot). Never write a bare number. On the phone only one sheet is open at a time (the page closes the others and tags `body.modal-open`, which quiets everything underneath), and there is one toast lane per screen.
2. **Gate phone-only JS by `ED.phone`** (`window.__ED`). Do not branch on user agent. Touch-only behaviour keys off `isTouch`, edition behaviour off `ED`. Desktop must never lose a feature because the phone omitted it; a phone omission is a choice recorded in the feature matrix.
3. **Every action has both homes.** A new action needs a desktop control or key and a phone control (or an explicit `desktopOnly` / `phoneOnly` entry with a reason) in `qa/parity-matrix.json`.
4. **Phone UX minimums:** targets at least 48 px (never under 44), gaps at least 8 px, safe-area insets on fixed elements, no overlap with other controls or the centre reticle, no horizontal scroll, labelled buttons in plain sentence case, no timers or countdowns in the UI, no `backdrop-filter`.
5. **Do not touch the low-light themes (red, green) or Easy text mode** except to verify them. Cartoon violence only.
6. **Test both editions** before declaring done with the one command `node qa/parity-check.js` (CSS scope and stacking lint, service worker rules, feature matrix, desktop golden screens, a real-Chrome service worker test, then a sweep of every screen at 390x844, 844x390 and 1400x860 through `qa/measure-ui.js`). `--quick` skips the sweep. Phone behaviour that screenshots cannot show (Back button, wake lock, haptics, tilt, lost graphics, governor) is `node qa/phone-features-check.mjs`. One headless Chrome window at a time (the harness tracks its PID and kills only that tree). A golden that changes on purpose needs `--update-goldens` and a line in `QA-LOG.md`.
7. **Update `sw.js` `VERSION`** on every change to `index.html` or other shell files (and the on-screen version). Bump `ASSETS` only if an asset's content changes under the same filename. Keep the `MINE` regex exact so only `squall-cove-*` caches are touched; never `caches.match()` globally; never cache `manifest.webmanifest`.
8. **Shared origin:** all storage keys and caches carry the `squall-cove` prefix. Do not change manifest `id`, `scope` or `start_url` without telling Robert (he must reinstall).
9. **Saves stay compatible both ways.** A desktop save must load on the phone (trimmed with a toast) and a phone save on desktop. Do not rename persisted keys.
10. **Budgets:** phone draw calls at most 700, DPR cap 1.5, first download at most 20 MB sandbox / 30 MB battle, no new default heavy asset on phone. Check `?perf=1` numbers if you add geometry, particles or textures.
11. **Record it:** add a line to `QA-LOG.md` (what changed, editions tested, viewport sizes, result) and update the plan or matrix if scope changed.
12. **Never push, deploy or commit to a shared branch without Robert's explicit approval.** Work stays on the local branch / worktree until he says so.
